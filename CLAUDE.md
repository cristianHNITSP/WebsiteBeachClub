## Comandos

**Desarrollo en contenedor** (`docker-compose.dev.yml`, nunca en el servidor). Las dependencias se instalan DENTRO: `node_modules` vive en un volumen del contenedor (binarios musl), no en el host. El código llega por bind-mount y el contenedor corre como uid 1000, así que lo que genera (shadcn, `package.json`) queda de tu usuario.

```bash
docker compose -f docker-compose.dev.yml up -d --build          # Vite + HMR en http://localhost:5176
DEV="docker compose -f docker-compose.dev.yml exec frontend-dev"
$DEV npm install <paquete>
$DEV npx shadcn@latest add <componente>                          # shadcn/ui → src/components/ui/
$DEV npx shadcn@latest add @react-bits/<Nombre>-JS-TW            # React Bits → mover a src/components/bits/
$DEV npm run lint && $DEV npm run build                          # lo mismo que corre CI
```

Frontend: sin tests; la verificación es lint + build (scripts de `frontend/package.json`: `dev`, `build`, `lint`, `preview`).

**Backend** (en el mismo `docker-compose.dev.yml`: `api`, `celery`, `postgres`, `redis`; antes, `cp backend/.env.example backend/.env` y cambiar las contraseñas). Detalle en `backend/README.md`:

```bash
$DEV api uv run pytest -q                       # pruebas (base aparte: beachclub_pruebas)
$DEV api uv run ruff check . && $DEV api uv run ruff format --check .
$DEV api uv run alembic upgrade head            # migraciones
$DEV api uv run pip-audit                       # CI falla si hay vulnerabilidades
$DEV api uv add <paquete>                       # y luego: up -d --build api celery
```

En desarrollo `celery` se reinicia solo al cambiar el código (`watchfiles`); en producción, al desplegar. API en `http://localhost:8000/api/docs` (solo desarrollo) y, desde el panel, por el proxy `/api` de Vite. Postgres no publica puerto: `$DEV postgres psql -U beachclub_migraciones beachclub`.

Despliegue (ver `docs/deploy-config-REFERENCIA.md`):

- **Push a `main` = despliegue a producción.** `.github/workflows/ci.yml` corre lint, build, `npm audit` (solo avisa) y el build de la imagen. Si pasa, su job `deploy` llama a `deploy.yml`, que entra por SSH al droplet, regenera `.env` desde los Secrets y corre `scripts/deploy.sh`. `development` y los PR solo prueban.
- En el servidor: `./scripts/deploy.sh --dry-run` valida sin tocar nada.

Probar la imagen de producción en local (con un certificado autofirmado):

```bash
S=$(mktemp -d); mkdir -p $S/live/prueba.local
openssl req -x509 -nodes -newkey rsa:2048 -days 1 -subj /CN=prueba.local \
  -keyout $S/live/prueba.local/privkey.pem -out $S/live/prueba.local/fullchain.pem
docker build --target prod -t bc-test frontend
docker run --rm -e BEACHCLUB_DOMINIO=prueba.local -v $S:/etc/letsencrypt:ro -p 8443:443 bc-test
curl -k --resolve prueba.local:8443:127.0.0.1 https://prueba.local:8443/admin   # 200
# Con la API y las fotos de desarrollo: --network beachclub-dev_default -v beachclub-dev_fotos:/datos/fotos:ro
```

## Arquitectura del frontend

- **La URL es la fuente de verdad** de "en qué pantalla estoy y con qué configuración": recargar, volver atrás o compartir el enlace deja todo igual. No guardes estado de pantalla en `useState`.
  - Website (`WebsiteApp.jsx`, **OCULTA hoy**, ver `lib/producto.js`; rutas reales): `/`, `/habitaciones`, `/habitaciones/:id`, `/mi-cuenta`, `*` → aviso. La configuración va en `?parámetros` con el hook `useParametros(defaults)` (`src/hooks/`): los valores por omisión no se escriben y los cambios reemplazan la entrada del historial. Filtros, orden, página y búsqueda en `/habitaciones`; fechas, huéspedes, extras y paso de la reserva en el detalle; `?seccion=` en la cuenta; `?destacadas=` en inicio. Lo que es del visitante (favoritos, reservas canceladas) va en `localStorage` con `useEstadoPersistente`. Fechas en la URL como `AAAA-MM-DD` en hora local (`src/lib/fechas.js`, nunca `toISOString`).
  - Admin (`AdminApp.jsx`): `/admin/<slug>` en español (`tablero`, `habitaciones`, `editar-habitacion/:id`…; tabla `SLUG`). Los ids internos de página (`rooms`, `calendar`…) no cambiaron: solo se traducen en la frontera con la URL. **Login único en `/entrar`** (website y panel): el rol decide a dónde llega (personal → panel o la pantalla que pidió con `?volver=`; huésped → `/mi-cuenta`, nunca al panel). Sesión REAL contra la API: `src/lib/sesion.js` + `src/lib/api.js` (cookies HttpOnly, CSRF de la cookie `frida_csrf`, ante un `401` renueva una vez y reintenta; **12 h como máximo**: al vencer manda al login con `?volver=`). En desarrollo, `docker compose -f docker-compose.dev.yml exec api python -m app.cli sembrar-desarrollo` crea `gerente` y `recepcion` (sus claves están en `backend/README.md`, "Cuentas de prueba"; el login ya no las muestra). Estado **"verificando"** mientras pregunta `GET /api/auth/yo`: `RutaProtegida` (`components/marca/`) no monta Mi cuenta ni el panel hasta verificar y muestra "Verificando tu sesión…". Cerrar sesión SIEMPRE por `/salir?a=` (`rutaSalir()`): si se cerrara en la misma pantalla, su guardia redirigiría al login antes de navegar. `AdminApp.FULL_PAGES` siguen avisando `onDirtyChange` y `NavGuardModal` protege los cambios sin guardar en la navegación interna.
- **Estilos, dos mundos**:
  - **Admin**: variables CSS en `src/index.css` (`:root`, `.dark`, `.high-contrast`, `.dark.high-contrast`), paleta teal, espejo JS en `src/tokens.js`, componentes `@/components/frida`, `admin/admin.css` + `*.module.css`.
  - **Website + admin** (todo el panel desde la fase 1): Tailwind v4 + shadcn/ui (`src/components/ui/`, estilo `radix-maia`) + React Bits (`src/components/bits/`) + `website/website.css` y `*.module.css`. Paleta floral del logo en `src/website/site.css`, declarada en **`body.site`**. La activa el hook `usePaletaSitio()` (`src/hooks/`), que usan `WebsiteApp` y `admin/pages/LoginPage`: pone `site` en `<body>` al montar y lo quita al desmontar, así los portales de Radix la heredan y el resto del admin nunca la ve. Para pasar otra pantalla del admin al diseño nuevo: `usePaletaSitio()` + componentes de `ui/`/`bits/`.
  - `site.css` va **sin preflight** (no toca al admin) y con utilidades **sin capa** (si no, el `* { margin:0; padding:0 }` sin capa de `index.css` les ganaría). Se importa **primero** en `main.jsx`: ante empate de especificidad gana el `*.module.css`. No cambies ese orden.
- **`ThemeContext`**: oscuro, tamaño de texto (vía `zoom`), alto contraste y reducir movimiento. Clases en `<html>`, persistidas en `localStorage` (`frida-*`). `App.jsx` pasa `reduceMotion` a `MotionConfig` de framer-motion.
- **Componentes base**: admin → `@/components/frida` (barrel: `Button`, cards, `Field`/`Input`, `Skeleton*`, `useToast`, `StatCard`, `DataTable`…); website → `@/components/ui/*` de shadcn (usan `cn` del paquete `cn`, de shadcn) y `@/components/bits/*`. La website solo reutiliza de `frida` `SectionHeader` y `useToast`: **no edites `frida` pensando en la website**, es del admin. `@` = `src/`. Iconos: website con `@phosphor-icons/react`; admin con Material Symbols.
- **React Bits**: GSAP (`SplitText`), WebGL con ogl (`Aurora`, solo en el login) y canvas (`ClickSpark`, en el hero) **no obedecen a `MotionConfig`**: cada uso comprueba `useTheme().reduceMotion` y ofrece versión quieta. Como WebGL/canvas no entienden `var()`, leen los tokens con `leerToken()` (`src/lib/tokens-css.js`). Todos importan de `framer-motion`, no de `motion/react`.
- **Imágenes: esqueleto global** (`src/lib/esqueletoImagenes.js`, activado en `main.jsx`, CSS al final de `index.css`): toda `<img>` muestra brillo de carga hasta su `load` y, si falla, un bloque neutro (sin icono roto ni texto alternativo). No envuelvas cada imagen; para excluir una (p. ej. sobre fondo oscuro) usa `data-sin-esqueleto`. **Fotos que pueden no existir o fallar** (habitaciones y todo lo que venga de la API): `components/marca/Imagen.jsx`, que llena su contenedor y pinta sus estados: esqueleto, "Imagen no anexada" (sin `src`), "Imagen no disponible" con Reintentar (si falla) y `cargando` (aún sin dirección). Nunca un hueco vacío.
- **Hero de la website**: fondo con fotos reales de Chelem y Chuburná (`website/components/PortadaFotos.jsx`, WebP 1920/1080 en `public/img/portada/`), una por palabra del rotador; entrada "desde el horizonte" en CSS (framer no interpola ese `clip-path`), fundido al cambiar y deriva lenta. Son **CC BY-SA 2.0**: el crédito vive en el pie de página y en `public/img/portada/CREDITOS.md`; si se cambian por fotos propias, quitar ambos. El velo (`.hero__overlay`) está medido para AA del texto blanco en las tres fotos: si cambias una foto, vuelve a medir. Nada de pastillas de color detrás de palabras ni rótulos en mayúsculas en la navegación: el usuario los lee como "plantilla de IA".
- **Logotipo**: `website/components/Wordmark.jsx` (corona de flores SVG + FRIDA en Chewy, decidido con el usuario), no el PNG. Sobre fondo oscuro la corona se aclara (`.corona` en `website.css`).
- **Tipografía (website + login)**: tres roles y una escala, en `site.css`. **Chewy** solo el logotipo; **Oswald** títulos, cifras y rótulos (clase `.rotulo`: mayúsculas, 500, `--tracking-rotulo`); **Cabin** todo el texto. Tamaños SOLO con `--fs-xs … --fs-hero`: nada de `px`/`rem` sueltos. El admin sigue con Noto Serif + Manrope.
- **Componentes de marca** (`src/components/marca/`, compartidos por website y admin; úsalos antes de crear otro): `Wordmark`, `Selector` (GlideSelect), `SelectorFechas` (Calendar animado), `Encabezado`, `Pista` + `GrupoPistas` (WarmTooltip: las etiquetas flotantes van SIEMPRE con esto, no con el Tooltip de shadcn), `BotonDestacado` (Magnet de React Bits topado a 5 px + `Button` de shadcn plano con relleno orquídea que nace del cursor + iconos "vivos" según su significado (tabla `ANIMACION` por nombre de icono de Phosphor; los fragmentos se aplanan y solo se anima el icono, nunca el texto) + resorte al presionar; LA acción principal de cada pantalla. Sin brillos ni destellos: el usuario los rechazó; el imán es la única excepción a "hover solo por sombra" y se apaga con reducir movimiento), `BotonTema` (claro/oscuro con círculo), `TarjetaCifra` (SpotlightCard + CountUp), `ConfirmarDescarte` (AlertDialog de shadcn), `Paginador` (anterior / números con marca deslizante / siguiente; página en la URL con `useParametros`).
- **Avisos del panel** (`/admin/avisos`, `admin/pages/AvisosPage.jsx`): `admin/avisos.js` es la caché de `/api/admin/avisos` (un almacén con `useSyncExternalStore` para la campana, la insignia de la SideNav y la página); leído y borrado van a la API, por persona. **En vivo:** `lib/eventos.js` mantiene UNA conexión SSE (`/api/eventos`) con contador de oyentes; `escucharEventos(fn)` la usan los avisos (recargan y hacen sonar un toast si lo causó otra persona) y `useReservas` (la Línea de tiempo se recarga sola). - **Lint**: `no-unused-vars` no entiende JSX sin el plugin de React, así que `eslint.config.js` ignora nombres (y parámetros) en Mayúscula y `motion`. `useTheme`/`useToast` están permitidos junto a su Provider, y `components/ui/**` (generado por shadcn) puede exportar sus `*Variants`.

## Reglas de diseño (resumen, contrato completo en `docs/SISTEMA-DE-DISENO.md`)

Website: paleta floral del logo (morado `#7A32C0`, dorado `#E8A828`, flores turquesa/orquídea/rojo/naranja/hoja; §2.4). Admin: teal original. Tipografía: Noto Serif + Manrope, Chewy solo para el logotipo y acentos. Reglas heredadas de SIMDES para las dos. **La website ya cumple; el admin no** (inventario en §12). **Código nuevo o tocado: cumple. No hagas barridos masivos sin que te lo pidan.**

- **Cero hex en componentes.** Todo color es un token: website en `site.css` (`body.site`, `.dark body.site`, `.high-contrast body.site`…), admin en `index.css`. Texto sobre una flor: su `--flor-*-fg`, nunca un blanco fijo (sobre `--flor-rojo` el blanco no pasa AA).
- **Contraste AA (4.5:1) auditado** para cada par texto/fondo nuevo. En el admin fallan hoy `--primary` sobre fondo oscuro (2.77) y el blanco sobre `--gold`/`--secondary`.
- **Translucidez con alfa** (`color-mix(… transparent)` + `box-shadow: inset`), **no `backdrop-filter: blur()`**, sobre todo en lo fijo (navbars) o animado: se recalcula en cada cuadro de scroll.
- **Hover solo por sombra.** Nada de `translateY` ni `whileHover={{ y }}`. Entradas: subida corta (~10 px) + opacidad, sin blur.
- **Separadores prohibidos en texto visible:** `—`, `|`, ` + `, runs decorativos, y `—` como "sin dato". Usar punto, coma, dos puntos, paréntesis o flecha (`12 abr → 15 abr`). `·` solo como último recurso.
- **Sin spinner encima del texto de un botón** (disabled + icono→spinner + etiqueta oculta, ancho estable). Avisos con `useToast`, nunca `alert()`. Carga con `Skeleton*` de la silueta real y altura fija.
- Todo debe funcionar con **oscuro + alto contraste + tamaño de texto + reducir movimiento** a la vez. Texto nuevo en `rem`, botones-icono con `aria-label`, táctiles ≥ 44 px, móvil primero (360 px).

## Configuración por entorno: fail fast, nada escrito a mano

Toda URL de servicio, credencial o dominio va en variables de entorno, nunca como literal en el código. Si falta una obligatoria, el proceso **no arranca** y dice qué falta; un valor de relleno (`change-me`) cuenta como ausente. Hoy aplica así:

- En producción, `.env` lleva `DOMINIO` y los secretos del backend (`POSTGRES_PASSWORD`, `API_DB_CLAVE`, `JWT_SECRETO`, `CLAVE_WEBHOOKS`; opcional `BRAVE_SEARCH_CLAVE`): `docker-compose.yml` los exige con `${…:?…}` y `deploy.sh` los comprueba (largo, sin relleno) antes de tocar nada.
- Al añadir una variable nueva: **si es secreta** (contraseña, clave), Secret en GitHub, línea en el heredoc del `.env` de `deploy.yml`, comprobación en `deploy.sh` y su fila en `docs/deploy-config-REFERENCIA.md` (en desarrollo, `backend/.env`). **Si no es secreta** (entorno, usuarios, nombres de base, direcciones internas), va **fija** en `docker-compose.yml`/`deploy.sh` (y `docker-compose.dev.yml`), nunca en `.env`. Las `VITE_*` se resuelven **al compilar**.

## Nginx y despliegue: trampas conocidas

- `frontend/nginx.conf.template` pasa por `envsubst` con `NGINX_ENVSUBST_FILTER=^BEACHCLUB_`. **Nuestras variables llevan el prefijo `BEACHCLUB_`.** Sin el filtro, `$host`/`$uri` quedarían vacíos.
- **`/api/` usa el resolver de Docker y el destino en variable** (`set $api http://api:8000`): Nginx arranca sin la API y no se queda con su IP vieja. No lo cambies a un `proxy_pass http://api:8000` fijo. `X-Forwarded-For` se **sobrescribe** con `$remote_addr` (la auditoría y el límite de intentos confían en él).
- **Fotos:** `/media/fotos/` solo sirve la forma exacta `<uuid>/<uuid>/<uuid>-<ancho>.webp` del volumen `fotos` (solo lectura); en desarrollo las sirve la API por el proxy de Vite.
- **Ningún `location` lleva `add_header`**: Nginx descartaría en ese location los headers de seguridad del `server`. La caché se pone con `expires`.
- La plantilla va **horneada en la imagen**, no montada: un bind-mount de un solo archivo sigue el inodo viejo tras un `git pull`.
- `docker-compose.yml` fija `image: beachclub-frontend:latest` porque el rollback de `deploy.sh` re-etiqueta la imagen anterior con ese nombre. No lo quites.
- `docs/deploy-config.local.md` tiene los valores reales del servidor y está en `.gitignore`. **Nunca lo commitees ni pegues su contenido en otro archivo.**
